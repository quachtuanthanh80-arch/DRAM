# Formal Verification Suite for Q-Shield Memory Controller

This directory contains the formal property specifications, SystemVerilog Assertions (SVA), and SymbiYosys (`sby`) proof configurations for the **Q-Shield** memory controller. Verification is conducted using **SymbiYosys (SBY)** with the **Z3 SMT solver** (alongside Boolector and Yices2 support) to verify safety invariants, deadlock freedom, and security bounds.

## 🛠️ 2. Formal Verification Methodology

### 1. Toolchain & Solver Configurations
- **Framework**: SymbiYosys (SBY) v0.38+ / v0.69 (YosysHQ formal hardware verification engine).
- **SMT Solvers**:
  - **Z3** (v4.12+): Primary SMT solver used for non-linear arithmetic and bit-vector theories (`QF_ABV`).
  - **Boolector / Bitwuzla**: Used as secondary solvers for bit-level bit-vector decision procedures.
  - **Yices2**: Used for high-speed linear arithmetic induction.
- **Engine Selection**: `smtbmc` (Bounded Model Checking with $k$-induction support).
- **Proof Timeout**: 300 seconds per individual specification.

### 2. Universal Adversarial Quantification (Unconstrained Inputs)
In traditional testbenches, stimulus generators are constrained by probability distributions. In SymbiYosys:
- Command inputs (`i_cmd_valid`, `i_cmd_addr`, `i_cmd_rw`, `i_cmd_qos`) are left **completely unconstrained** (no artificial `assume()` statements restricting input arrival patterns).
- The SMT solver universally quantifies across **all mathematically feasible input combinations**, meaning properties hold under arbitrary worst-case, pathological, and adversarial software sequences.

### 3. Deliberately Omitted Assumptions
To prevent false-positive verification ("vacuous proofs"), the following assumptions were **intentionally excluded**:
- *No assumption on benign access order*: Aggressors can access arbitrary physical addresses in consecutive cycles.
- *No assumption on DRAM bus bandwidth*: Bursts can arrive at maximum wire speed.
- *No assumption on downstream receiver readiness*: Downstream interfaces can deassert `ready` at any arbitrary clock cycle.

## 🔍 3. Property Definitions & Mathematical Targets

### 1. `sdc_resilient_filter.sv` (`formal_sdc_filter.sby`)
- **Natural Language**: The counter in the dual-hash sketch must always be greater than or equal to the actual number of activations for that row address within the current epoch.
- **Mathematical Form**:
  $$\forall R \in \text{RowAddressSpace}, \quad \min\left(C_1[h_1(R)], \, C_2[h_2(R)]\right) \ge N_{\text{act}}(R)$$
- **Scope**: Covers overflow protection, reset behavior, and zero false negatives.

### 2. `reorder_buffer_rob.sv` (`formal_rob.sby`)
- **Natural Language**: Read requests targeting the exact address of an outstanding write request currently held in the reorder buffer must never be scheduled to DRAM before the write is committed.
- **Mathematical Form**:
  $$\forall i < j, \quad \left(\text{ROB}[i].\text{addr} = \text{ROB}[j].\text{addr} \land \text{ROB}[i].\text{is\_write} \land \neg\text{ROB}[j].\text{is\_write}\right) \implies \text{IssueTime}(j) > \text{IssueTime}(i)$$
- **Scope**: Covers RAW hazard detection, circular buffer wrap-around, and in-order retirement.

### 3. `axi4_skid_buffer.sv` (`formal_skid_buffer.sby`)
- **Natural Language**: The skid buffer must never drop beats, duplicate beats, or introduce latency bubbles when downstream logic is asserted ready.
- **Mathematical Form**:
  $$o_{\text{valid}} \land o_{\text{ready}} \implies \text{BeatIndex}_{\text{out}} = \text{BeatIndex}_{\text{in}}$$
- **Scope**: Covers backpressure decoupling, 2-deep register state transitions, and reset initialization.

### 4. `ecc_scrubber.sv` (`formal_ecc_scrubber.sby`)
- **Natural Language**: All single-bit errors in a 72-bit codeword must be corrected to the original 64-bit data. All double-bit errors must trigger an alert flag and never produce unflagged corruption.
- **Mathematical Form**:
  $$\forall e \in \mathbb{F}_2^{72}, \quad w_H(e) = 1 \implies \text{Dec}(C \oplus e) = D \quad \land \quad w_H(e) = 2 \implies \text{Alert} = 1$$
- **Scope**: Covers Hsiao SEC-DED syndrome generation, bit error injection, and poison signaling.

### 5. `ddr5_cmd_engine.sv` (`formal_cmd_engine.sby`)
- **Natural Language**: Physical command sequences must never violate JEDEC timing intervals between consecutive states, and active rows must be closed before $t_{\text{RAS\_max}}$.
- **Mathematical Form**:
  $$t_{\text{ACT}\to\text{ACT}} \ge t_{\text{RRD\_L}}, \quad t_{\text{ACT}\to\text{PRE}} \ge t_{\text{RAS\_min}}, \quad t_{\text{ActiveDuration}} \le t_{\text{RAS\_max}}$$
- **Scope**: Covers JEDEC state transitions, precharge timing, and RowPress duration clamping.

## ⚠️ 4. What Is NOT Proved (Verification Boundaries)

To maintain academic rigor, the limits of these formal proofs are explicitly stated:
1. **Not a Full-Chip System Proof**: Proofs are conducted on unit and subsystem interfaces. Global top-level interactions between the AXI slave frontend and DFI PHY adapter are verified via cycle-accurate simulation and Cocotb regression rather than monolithic end-to-end formal equivalence.
2. **Not Physical Analog Dynamics**: The formal model assumes ideal digital clocking. Analog effects such as signal attenuation, jitter, voltage droop, temperature-dependent charge leakage, and PCB crosstalk are outside the mathematical domain of SVA.
3. **Not Hardware Trojan / Side-Channel Immunity**: Formal proofs verify specified assertions against the threat model. Side-channel vulnerabilities (e.g., differential power analysis, microarchitectural timing channels) are not modeled by these assertions.

## 🚀 5. How to Run Formal Proofs

### 1. Prerequisites Installation
To install SymbiYosys, Yosys, and Z3 on Ubuntu / WSL2:
```bash
sudo apt-get update
sudo apt-get install -y yosys z3
# Install SymbiYosys from YosysHQ
pip install sby
```

### 2. Run All Proofs
```bash
cd formal
bash run_all_formal.sh
```
All proof logs and SMT trace artifacts are saved to `logs/` and summarized in `reports/summary.json`.

### 3. Run an Individual Specification
```bash
cd formal
sby -f formal_sdc_filter.sby
```

### 4. Inspecting Counter-Examples (Debugging Failures)
If an assertion fails, SBY outputs a VCD waveform file showing the exact counter-example sequence:
```bash
# SBY generates trace in <spec_name>/engine_0/trace.vcd
gtkwave formal_sdc_filter/engine_0/trace.vcd
```
